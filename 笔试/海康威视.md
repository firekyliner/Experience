## 一、客观题

### 第1题：new[] 分配的动态数组应如何释放（不定项截图中的单选）

**题目：** 已执行如下代码，若要正确释放申请的两块动态数组内存，应选择哪组语句？

~~~cpp
int* pInt = new int[4];
A* pClassA = new A[4];
~~~

**选项：**

- A. `delete[] pInt; delete pClassA;`
- B. `delete pInt; delete[] pClassA;`
- C. `delete[] pInt; delete[] pClassA;`
- D. `delete pInt; delete pClassA;`

**答案：C。**

**解析：** 两个指针均由 new[] 创建数组，必须分别用 delete[] 释放。对类 A 的数组，delete[] 还会对数组元素逐个调用析构函数。混用 new[] 和 delete 会导致未定义行为，不能因元素是 int 而省略方括号。

### 第2题：排序算法的稳定性

**题目（根据对话中的提问恢复）：** 归并排序、堆排序、冒泡排序和快速排序中，哪些属于非稳定排序？

**答案：** 常规实现下，**堆排序和快速排序**为非稳定排序；归并排序和冒泡排序为稳定排序。

| 算法 | 常规实现是否稳定 | 原因 |
| --- | --- | --- |
| 归并排序 | 稳定 | 合并时相等元素优先取左侧，保留原先相对顺序 |
| 堆排序 | 不稳定 | 建堆及堆顶与末尾交换可能改变相等元素的相对顺序 |
| 冒泡排序 | 稳定 | 仅交换严格逆序的相邻元素，相等元素不交换 |
| 快速排序 | 不稳定 | 常规分区交换可能改变相等元素的相对顺序 |

**注意：** 稳定性与具体实现有关；例如合并时相等元素先取右侧，归并排序也可能不稳定。此题采用教材中的常规实现口径。

## 二、C/C++ 基础问答

### 第1题：指针占用多少字节

**题目（题干未完整保留，根据对话主题恢复）：** C/C++ 指针的大小是多少？与所指向的数据类型有关吗？

**参考答案：** 在常见的 32 位平台中，普通对象指针通常占 4 字节；在常见的 64 位平台中通常占 8 字节。指针大小由平台 ABI、指针类别等决定，不由所指向对象的大小决定。对于常见平台，sizeof(int*)、sizeof(char*) 和 sizeof(double*) 相同，但 C++ 标准不保证所有指针类别在所有平台上大小相同；应以实际平台的 sizeof 结果为准。

~~~cpp
#include <iostream>
using namespace std;
int main() {
    cout << sizeof(int*) << " "
         << sizeof(char*) << " "
         << sizeof(double*) << '\n';
}
~~~

### 第2题：a += b 与 a = a + b 的区别

**原题：** 请列出以下两个表达式的区别，必要时举例说明。

~~~cpp
a += b;
a = a + b;
~~~

**参考答案：**

1. **含义：** 对普通数值变量，两者通常都将 a 与 b 的和赋回 a；复合赋值不是无条件等同于简单的文本替换。
2. **左操作数求值次数：** a += b 的左操作数只求值一次；a = a + b 在表达式中出现两次 a，若 a 是带副作用的表达式，行为可能不同。
3. **运算符重载：** 对类对象，a += b 可调用 operator+=，a = a + b 则可调用 operator+ 再调用赋值运算符；两者语义、效率甚至合法性都可能不同。
4. **类型转换：** 对内置算术类型，复合赋值会按相应运算规则计算并将结果转换回左操作数类型；不能笼统认为 += 一定更精确或一定更快。
5. **效率：** 对简单内置变量，优化编译器往往生成相同或相近的机器代码，不能断言 += 必然更快。

**举例 1：左操作数求值次数不同。**

~~~cpp
#include <iostream>
using namespace std;

int calls = 0;
int value = 1;
int& getRef() {
    ++calls;
    return value;
}

int main() {
    getRef() += 2;
    cout << calls << " " << value << '\n'; // 1 3

    calls = 0;
    value = 1;
    getRef() = getRef() + 2;
    cout << calls << " " << value << '\n'; // 2 3
}
~~~

**举例 2：类类型可分别重载两种运算。**

~~~cpp
struct Counter {
    int value;
    Counter& operator+=(int x) {
        value += x;
        return *this;
    }
    Counter operator+(int x) const {
        return Counter{value + x};
    }
};
~~~

### 第3题：编译期多态与运行期多态的概念、区别和优缺点

**原题：** 编译期多态与运行期多态分别是什么？列出它们的区别和优缺点。

**参考答案：**

1. **实现方式：** 编译期多态通常由函数重载、运算符重载和模板实现；运行期多态通常由继承、虚函数及基类指针或引用实现。
2. **绑定时间：** 编译期多态在编译阶段确定具体调用；运行期多态通过虚函数机制在运行时根据对象的动态类型进行分派。
3. **执行效率：** 编译期多态通常没有虚函数动态分派开销，并可能更易内联；运行期多态通常存在间接调用开销，但编译器在能够确定动态类型时也可能去虚拟化。
4. **类型检查：** 编译期多态的重载匹配、模板实例化等在编译时检查；运行期多态的函数签名和重写关系同样受编译期检查，只是最终虚调用目标通常在运行时确定。
5. **扩展方式：** 编译期多态适用于已知类型和泛型算法；运行期多态适用于通过统一基类接口处理多种动态对象。

**编译期多态优点：** 通常执行效率较高，没有虚函数动态分派开销；可在编译期发现类型匹配错误；模板适合泛型编程。

**编译期多态缺点：** 具体调用关系通常需要在编译时确定；模板可能增加编译时间、错误信息复杂度和生成代码体积。

**运行期多态优点：** 可通过统一接口处理不同派生类对象，便于替换实现、动态扩展和面向接口编程。

**运行期多态缺点：** 虚调用通常有额外间接分派成本；通常需要继承体系和虚函数设计，增加部分对象布局与维护复杂度。

**简例：**

~~~cpp
#include <iostream>
using namespace std;

void print(int) { cout << "int\n"; }
void print(double) { cout << "double\n"; } // 重载：编译期多态

struct Animal {
    virtual ~Animal() = default;
    virtual void speak() const { cout << "Animal\n"; }
};
struct Dog : Animal {
    void speak() const override { cout << "Dog\n"; }
};

int main() {
    print(1);
    print(1.5);
    Dog dog;
    Animal& ref = dog;
    ref.speak(); // 运行期多态，输出 Dog
}
~~~

### 编程题 1：Person 类的深拷贝构造函数

#### 题目

已有 Person 类，包含姓名 char* name 和年龄 int age。原构造函数用 new char[strlen(name)+1] 为姓名分配动态内存，并通过 strcpy 拷贝；析构函数使用 delete[] name。**请在原有类的指定位置添加拷贝构造函数**，使复制 Person 对象后能正确输出姓名与年龄，且不发生重复释放。原图中给出的输出方法为 showPerson()，姓名和年龄之间用空格分隔。

#### 输入描述

输入一个姓名和一个整数年龄，中间可用空格或换行分隔。截图未提供姓名长度和年龄范围；下面的 ACM 示例使用 std::string 安全读取，再传给题目指定的 const char* 构造函数。

#### 输出描述

通过 Person 类的 showPerson() 输出复制后对象的姓名和年龄，中间以空格隔开。

#### 样例输入

~~~text
zhangsan
20
~~~

#### 样例输出

~~~text
zhangsan 20
~~~

#### 应填入原代码的核心部分

~~~cpp
Person(const Person& p) {
    name = new char[strlen(p.name) + 1];
    strcpy(name, p.name);
    age = p.age;
}
~~~

#### 思路

默认拷贝构造函数会逐成员复制，char* 仅复制地址，导致两个对象共享同一姓名缓冲区，析构时重复 delete[]。因此拷贝时应独立分配 strlen+1 字节、复制字符串并复制 age。时间和额外空间复杂度均为 O(L)，L 为姓名长度。

#### C++17（ACM 模式，保留题图的 char* 设计）

~~~cpp
#include <iostream>
#include <cstring>
#include <string>
using namespace std;

class Person {
public:
    char* name;
    int age;

    Person(const char* name, int age) {
        this->name = new char[strlen(name) + 1];
        strcpy(this->name, name);
        this->age = age;
    }

    // 原题要求补充的深拷贝构造函数
    Person(const Person& p) {
        name = new char[strlen(p.name) + 1];
        strcpy(name, p.name);
        age = p.age;
    }

    void showPerson() const {
        cout << name << " " << age << '\n';
    }

    ~Person() {
        delete[] name;
        name = nullptr;
    }
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string inputName;
    int inputAge;
    if (!(cin >> inputName >> inputAge)) return 0;

    Person p1(inputName.c_str(), inputAge);
    Person p2(p1);  // 验证拷贝构造
    p2.showPerson();
    return 0;
}
~~~

**易错点：** 原题仅要求添加拷贝构造函数；但这个拥有动态资源的类若还要支持 p2 = p1，仍需正确实现拷贝赋值运算符（Rule of Three），否则赋值时依然可能浅拷贝。实际项目优先使用 std::string 管理姓名，避免手动 new[]/delete[]。

### 编程题 2：判断一个整数是否为质数

#### 题目

输入一个大于 1 的整数，判断其是否为质数。

#### 输入描述

一个大于 1 的整数 n。截图未给出数值上限。

#### 输出描述

若 n 为质数，输出“质数”；否则输出“不是质数”。

#### 样例输入

~~~text
2
~~~

#### 样例输出

~~~text
质数
~~~

#### 思路

质数是大于 1 且只有 1 和自身两个正因数的整数。若 n 为合数，必有一个不超过 sqrt(n) 的因数，因此只需试除至平方根。用 i <= n / i 代替 i*i <= n，可避免 i*i 的整数溢出。时间复杂度 O(sqrt(n))，额外空间 O(1)。

#### C++17（ACM 模式）

~~~cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    if (!(cin >> n)) return 0;

    bool prime = n > 1;
    for (long long i = 2; i <= n / i; ++i) {
        if (n % i == 0) {
            prime = false;
            break;
        }
    }

    cout << (prime ? "质数" : "不是质数") << '\n';
    return 0;
}
~~~

**边界检查：** n=2、n=3 为质数；n=4、n=9 不是质数。若题目允许 n<=1，代码也会输出“不是质数”。
