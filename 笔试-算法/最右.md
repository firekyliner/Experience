### 第1题 TCP 慢启动需要经过多少个 RTT

**题目：**

某 TCP 连接使用慢启动算法，初始拥塞窗口 `cwnd = 1 MSS`，慢启动门限 `ssthresh = 32 MSS`。假设始终没有丢包，且每经过一个 RTT，`cwnd` 就会翻倍。问需要经过多少个 RTT 结束慢启动？

**答案：5 个 RTT。**

**解析：**

| 已经过的 RTT | 0（初始） | 1 | 2 | 3 | 4 | 5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `cwnd`（MSS） | 1 | 2 | 4 | 8 | 16 | 32 |

题目明确按每 RTT 翻倍计算，经过 $r$ 个 RTT 时有：

$$
\mathrm{cwnd}(r)=2^r\,\mathrm{MSS}
$$

达到门限的最小整数 $r$ 满足 $2^r\ge32$，所以 $r=5$。达到门限时退出慢启动，转入拥塞避免。

### 第2题 CAS 的 ABA 问题

**题目：**

并发编程中，CAS 操作的 ABA 问题是指什么？

**答案：**

一个共享变量起初是 A，被其他线程改成 B，之后又改回 A。原线程执行 CAS 时发现当前值仍是 A，便可能误以为变量从未改变，导致基于旧状态的操作错误成功。

**解析：**

~~~text
线程 T1：读取 A                  CAS(A, C) 成功
线程 T2：         A → B → A
~~~

CAS 只比较操作瞬间的值，不能判断中途是否变化。典型解决方案是将版本号与值一起比较，例如 $(A,1)\to(B,2)\to(A,3)$，即使值回到 A，版本号也已变化。也可以按具体场景使用带标记的原子引用等机制。

### 第3题 IP 地址与子网划分

**题目：**

某主机 IP 地址为 `192.168.10.130`，子网掩码为 `255.255.255.192`。求该主机所在子网的网络地址以及可分配主机地址数量。

**答案：网络地址为 `192.168.10.128`；可分配主机地址为 62 个。**

**解析：**

子网掩码为 `/26`，主机位有 $32-26=6$ 位；每个子网有 $2^6=64$ 个地址。最后一个字节的块大小为 $256-192=64$，130 落在 128～191 区间。

| 项目 | 结果 |
| --- | --- |
| 网络地址 | `192.168.10.128` |
| 广播地址 | `192.168.10.191` |
| 可用主机范围 | `192.168.10.129` ～ `192.168.10.190` |
| 可用主机数 | $2^6-2=62$ |

### 第4题 二维数组按行遍历更快的原因

**题目：**

对于大型二维数组，按行优先顺序遍历通常比按列优先顺序快得多，主要原因是什么？

**答案：按行访问与行优先存储的连续内存布局一致，具有更好的空间局部性，提高 CPU Cache 命中率，并利于硬件预取。**

**解析：**

在 C/C++ 等行优先存储环境中，同一行的相邻元素通常连续。按列遍历的连续两次访问往往相隔一整行，可能导致更多缓存未命中。该结论依赖存储布局：Fortran、MATLAB 等采用列优先存储时，列遍历通常更符合内存布局。

### 第5题 select 与 epoll 的区别

**题目：**

关于 I/O 多路复用中的 `select` 与 `epoll`，描述正确的是？

**答案：`select` 每次调用需要传入待监视的文件描述符集合，返回后通常需要遍历集合检查就绪状态；`epoll` 先注册关注的文件描述符，再由 `epoll_wait` 返回就绪事件，通常适合大量连接、少量活跃的场景。**

**解析：**

| 对比 | select | epoll（Linux） |
| --- | --- | --- |
| 关注集合 | 每次调用传入并复制集合 | 通过 `epoll_ctl` 注册、修改、删除 |
| 就绪结果 | 在返回的集合中检查就绪描述符 | `epoll_wait` 返回就绪事件 |
| 数量限制 | `fd_set` 常受 `FD_SETSIZE` 限制，常见默认值为 1024 | 不受固定的 1024 个 `fd_set` 限制，仍受文件描述符与系统资源限制 |
| 触发方式 | 水平触发语义 | 支持水平触发 LT 和边缘触发 ET |

注意：不能笼统认为 epoll 在任何场景都更快，也不能把其所有操作都说成严格 $O(1)$。使用 ET 时通常需采用非阻塞 I/O，并将就绪数据读/写至返回 `EAGAIN`。

### 第6题 LRU 页面置换的缺页次数

**题目：**

操作系统采用 LRU 页面置换算法，物理块数为 3，依次访问的页面为：

`7，0，1，2，0，3，0，4，2，3，0，3，2`

问一共发生多少次缺页？

**答案：9 次。**

**解析：**

下表中，物理块内容按“最久未使用 → 最近使用”排列。访问命中时也需要更新最近使用顺序。

| 访问页面 | 内存中的有效页面（LRU → MRU） | 缺页 |
| ---: | --- | :---: |
| 7 | 7 | 是 |
| 0 | 7, 0 | 是 |
| 1 | 7, 0, 1 | 是 |
| 2 | 0, 1, 2 | 是 |
| 0 | 1, 2, 0 | 否 |
| 3 | 2, 0, 3 | 是 |
| 0 | 2, 3, 0 | 否 |
| 4 | 3, 0, 4 | 是 |
| 2 | 0, 4, 2 | 是 |
| 3 | 4, 2, 3 | 是 |
| 0 | 2, 3, 0 | 是 |
| 3 | 2, 0, 3 | 否 |
| 2 | 0, 3, 2 | 否 |

总计 13 次访问，9 次缺页，缺页率为：

$$
\frac{9}{13}\times100\%\approx69.23\%
$$

### 第7题 `n & (n-1)` 的结果和用途

**题目：**

设整数 `n = 12`，表达式 `n & (n-1)` 的结果及常见用途是什么？

**答案：结果是 8；该表达式用于消去二进制表示中最低位的 1。**

**解析：**

~~~text
  12 = 1100
  11 = 1011
       ----
   & = 1000 = 8
~~~

应用包括：

1. 对正整数 `n`，利用 `(n & (n-1)) == 0` 判断其是否为 2 的幂。
2. 反复执行 `n &= n-1`，统计原整数二进制中 1 的数量（Kernighan 算法）。

判断 2 的幂时必须附加 `n > 0` 条件，避免 0 被误判。

### 编程题 1：二叉树中的最大路径收益

#### 题目

给定一棵非空二叉树，每个节点代表一个站点，其 `val` 是预估净收益（可为负）。父子站点间可以双向通行。选择一条非空、连续、无重复站点且不能分叉的简单路径，起终点可为任意节点，不要求经过根节点。返回路径上节点收益之和的最大值，无需返回具体路径。

给定接口：

~~~python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def max_path_sum(root: TreeNode) -> int:
    pass
~~~

#### 思路

后序 DFS：令 `dfs(node)` 返回从 `node` 出发、向下且不分叉的最大路径收益。对左右子树负贡献直接舍弃：

$$
L=\max(0,\mathrm{dfs}(node.left)),\qquad
R=\max(0,\mathrm{dfs}(node.right))
$$

以当前节点为路径最高点，可以同时连接左右两条分支；但向父节点返回时只能选择一侧，避免整条路径分叉。

$$
\mathrm{candidate}=node.val+L+R
$$

$$
\mathrm{dfs}(node)=node.val+\max(L,R)
$$

#### Python 参考代码

~~~python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val, self.left, self.right = val, left, right


def max_path_sum(root: TreeNode) -> int:
    best = float("-inf")

    def dfs(node):
        nonlocal best
        if node is None:
            return 0

        left = max(0, dfs(node.left))
        right = max(0, dfs(node.right))

        best = max(best, node.val + left + right)
        return node.val + max(left, right)

    dfs(root)
    return best
~~~

#### 示例与复杂度

~~~text
        -10
        / \
       9   20
          /  \
         15   7
~~~

最优路径为 `15 → 20 → 7`，最大收益 $15+20+7=42$。若所有节点收益都为负，必须返回其中最大的单节点值，不能默认返回 0。

- 时间复杂度：$O(n)$，每个节点访问一次。
- 额外空间：$O(h)$ 递归栈，$h$ 为树高，最坏为 $O(n)$。

### 编程题 2：长度不超过 k 的最大连续区间和

#### 题目

给定长度为 `n` 的整数数组 `scores`，其中元素可为负数。选取一个**非空连续区间**，且区间长度**不超过** `k`，使区间元素和最大，返回这个最大值。

~~~python
def max_window_sum(scores: list[int], k: int) -> int:
    pass
~~~

这里假设 `scores` 非空且 `k >= 1`。

#### 思路

令前缀和为 $P[0]=0$，$P[i]=\sum_{t=0}^{i-1}scores[t]$。以 $i-1$ 结尾的合法非空区间，其左边界 $j$ 满足：

$$
i-k\le j<i
$$

对应区间和为 $P[i]-P[j]$，因此只需维护合法左边界范围中最小的前缀和。使用双端队列保存前缀和递增的候选下标：先移除过期下标，使用队首更新答案，再按单调性插入当前下标。

#### Python 参考代码

~~~python
from collections import deque


def max_window_sum(scores: list[int], k: int) -> int:
    prefix = [0] * (len(scores) + 1)
    for i, value in enumerate(scores):
        prefix[i + 1] = prefix[i] + value

    q = deque([0])  # 候选前缀下标，对应前缀和值递增
    ans = float("-inf")

    for i in range(1, len(prefix)):
        # 确保左边界 j >= i-k
        while q and q[0] < i - k:
            q.popleft()

        # 先查询，再插入 i，以保证区间非空
        ans = max(ans, prefix[i] - prefix[q[0]])

        while q and prefix[q[-1]] >= prefix[i]:
            q.pop()
        q.append(i)

    return ans
~~~

#### 示例与复杂度

~~~python
max_window_sum([2, -1, 3, -2, 4], 3)  # 5，区间 [3, -2, 4]
max_window_sum([-5, -2, -8], 2)       # -2，必须选非空区间
~~~

- 时间复杂度：$O(n)$，每个下标最多入队、出队各一次。
- 额外空间：$O(n)$（前缀和与队列；若只保留必要的滚动信息可进一步优化）。

**调试易错点：** 正确导入语句是 `from collections import deque`，不是 `from collection import deque`；另外，不能将答案初始化为 0，否则全负数测试会出错。

### 编程题 3：支持 add / remove 的动态第 k 大元素

#### 题目

初始化时给定固定的 `k` 与初始宝石价值数组 `nums`。维护当前所有宝石组成的**多重集合**（允许重复价值），提供：

- `add(val)`：加入一个价值为 `val` 的宝石，返回当前第 `k` 大的价值。
- `remove(val)`：删除一个价值恰好为 `val` 的宝石并返回当前第 `k` 大的价值；保证要删除的价值存在。

每次 `add/remove` 结束后，当前宝石总数均不少于 `k`；初始数组可以为空或不足 `k`，但调用返回结果时一定满足上述保证。要求尽量降低单次操作复杂度。题目允许辅助的“清理堆顶已标记删除元素”“平衡两个堆”等步骤使用伪代码；下面给出完整 Python 参考实现。

#### 数据结构与不变量

维护两个堆：

1. `large`：**最小堆**，保存当前最大的 `k` 个有效元素；`large[0]` 就是第 `k` 大。
2. `small`：**最大堆**，保存其余有效元素。Python 用存负数的最小堆模拟。

有效元素必须满足：`large` 中的每个值都不小于 `small` 中的每个值；并且当总数至少为 `k` 时，`large` 中恰好有 `k` 个**有效**元素。

由于标准堆不支持高效按值删除，还需为两个堆分别维护：

- `large_count`、`small_count`：每个值在对应堆中**有效**的出现次数，解决重复值的归属问题。
- `large_del`、`small_del`：已经逻辑删除、等待出现在堆顶时清理的次数。
- `large_size`、`small_size`：两个堆有效元素总数，不把尚未物理弹出的延迟删除元素计入。

#### Python 参考代码

~~~python
import heapq
from collections import Counter


class KthLargest:
    def __init__(self, k: int, nums: list[int]):
        self.k = k
        self.large = []  # 最小堆：最大的 k 个有效元素
        self.small = []  # 最大堆：其余元素，以负数保存

        self.large_count = Counter()
        self.small_count = Counter()
        self.large_del = Counter()
        self.small_del = Counter()

        self.large_size = 0
        self.small_size = 0

        for value in nums:
            self._insert(value)

    def _clean_large(self):
        while self.large and self.large_del[self.large[0]] > 0:
            value = heapq.heappop(self.large)
            self.large_del[value] -= 1

    def _clean_small(self):
        while self.small and self.small_del[-self.small[0]] > 0:
            value = -heapq.heappop(self.small)
            self.small_del[value] -= 1

    def _balance(self):
        total = self.large_size + self.small_size
        target = min(self.k, total)

        # large 过多：把其中最小值转移到 small
        while self.large_size > target:
            self._clean_large()
            value = heapq.heappop(self.large)
            self.large_count[value] -= 1
            self.large_size -= 1

            heapq.heappush(self.small, -value)
            self.small_count[value] += 1
            self.small_size += 1

        # large 不足：把 small 中最大值转移进来
        while self.large_size < target:
            self._clean_small()
            value = -heapq.heappop(self.small)
            self.small_count[value] -= 1
            self.small_size -= 1

            heapq.heappush(self.large, value)
            self.large_count[value] += 1
            self.large_size += 1

        self._clean_large()
        self._clean_small()

    def _insert(self, value):
        self._clean_large()

        if not self.large or value >= self.large[0]:
            heapq.heappush(self.large, value)
            self.large_count[value] += 1
            self.large_size += 1
        else:
            heapq.heappush(self.small, -value)
            self.small_count[value] += 1
            self.small_size += 1

        self._balance()

    def add(self, val: int) -> int:
        self._insert(val)
        return self.large[0]

    def remove(self, val: int) -> int:
        # 多重集合：在任一含有有效 val 的堆中删除一份
        if self.large_count[val] > 0:
            self.large_count[val] -= 1
            self.large_size -= 1
            self.large_del[val] += 1
            self._clean_large()
        else:
            self.small_count[val] -= 1
            self.small_size -= 1
            self.small_del[val] += 1
            self._clean_small()

        self._balance()
        return self.large[0]
~~~

#### 示例

~~~python
obj = KthLargest(3, [4, 5, 8, 2])
print(obj.add(3))     # 4
print(obj.remove(5))  # 3
print(obj.add(10))    # 4
print(obj.remove(8))  # 3
~~~

#### 复杂度与注意事项

- 初始化：逐个插入，均摊 $O(n\log M)$。
- `add` / `remove`：均摊 $O(\log M)$，其中 $M$ 是两堆**实际存储的条目数**。
- 查询：清理完成后直接读取 `large[0]`，$O(1)$。
- 延迟删除可能使实际堆规模随操作历史增长，不能在不限制历史长度的情况下声称空间始终是 $O(n)$（当前元素数）。若需长期高频运行，可按失效条目比例周期性重建堆。

**关键区别：** 仅用一个大小为 `k` 的最小堆足以支持常规 `add`，却无法在其内部元素被删除后从剩余元素中找出补位值；因此支持任意 `remove` 时，需要额外维护剩余元素（此处是 `small` 堆）。
