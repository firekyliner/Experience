### 第 1 题：递增序列构建二叉排序树（单选）

**题目：** 使用序列 (4, 5, 6, 7, 8, 9, 10) 建立二叉排序树，建立好的二叉排序树是一棵（ ）。

A. 左向单支树  
B. 完全二叉树  
C. 右向单支树  
D. 满二叉树

**答案：C。**

**解析：** 按序插入且序列严格递增，新节点都成为现有最大节点的右孩子，形成向右倾斜的单链树；普通二叉搜索树不保证平衡。

### 第 2 题：最短二进制编码 / 哈夫曼编码（单选）

**题目：** 用二进制编码字符串“abcdabaa”，要求能够根据编码解码回原来的字符串，最少需要（ ）长的二进制字符串。

A. 18  
B. 14  
C. 12  
D. 24

**答案：B（按字符的前缀编码 / 哈夫曼编码理解）。**

**解析：** a、b、c、d 的频率依次为 4、2、1、1。构造哈夫曼树，可令 a 长度 1、b 长度 2、c/d 长度 3，总位数为 `4×1+2×2+1×3+1×3=14`。若要求每种字符固定长度编码，则 4 种字符各需 2 位，共 16 位，但选项没有 16，因此本题按变长前缀编码理解。**复盘：** 对话中首次回答曾误写 A，最终应以 B 为准。

### 第 3 题：HASH 字符串匹配复杂度（单选）

**题目：** 主串长度为 n，模式串长度为 m，HASH 匹配算法的时间复杂度为（ ）。

A. `O(nm)`  
B. `O(m)`  
C. `O(n)`  
D. `O(n+m)`

**答案：D（典型滚动哈希的平均 / 期望复杂度）。**

**解析：** 计算模式串及初始窗口哈希约 `O(m)`，沿主串滚动匹配约 `O(n)`。存在大量哈希冲突且逐次验证时，朴素 Rabin–Karp 最坏复杂度可能达到 `O(nm)`。

### 第 7 题：RNN、LSTM、GRU（多选）

**题目：** 关于循环神经网络（RNN）及其变体（LSTM、GRU），以下哪些说法正确？

A. 传统 RNN 容易出现梯度消失问题，影响长序列学习能力  
B. LSTM 只能用于自然语言处理（NLP），不能用于时间序列预测

### 第 12 题：K-means 部分簇不再变化（单选）

**题目：** 使用 K-Means 对用户进行聚类，选择 k=5 运行算法后，若某个簇在后续迭代中不再有样本改属，而其他簇仍在变化，则算法的收敛行为是（ ）。

### 第 14 题：最长连续递增子序列的 Java 代码填空（页面标单选）

**题目：** 给定整数序列，求其最长**连续**递增子序列长度，补全原代码中的 `if(a[i] > a[i-1])` 分支。原图未包含可辨认的选项。

**答案：** `len[i] = len[i - 1] + 1;`

**补全后代码（额外增加空数组保护，原截图未要求）：**

~~~java
public int DP3(int[] a) {
    if (a == null || a.length == 0) return 0;
    int length = 1;
    int[] len = new int[a.length];
    len[0] = 1;
    for (int i = 1; i < a.length; i++) {
        if (a[i] > a[i - 1])
            len[i] = len[i - 1] + 1;
        else
            len[i] = 1;
        if (length < len[i])
            length = len[i];
    }
    return length;
}
~~~

**解析：** 只有当前元素大于紧邻的前一个元素，连续递增长度才能继承并加一；否则重新从 1 开始。

### 第 15 题：两个进程并发修改共享变量（单选）

**题目：** 两个并发执行的进程 P1 和 P2 共享初值为 1 的变量 x。P1 执行 `Load R1,x → inc R1 → Store x,R1`，P2 执行 `Load R2,x → dec R2 → Store x,R2`。两个操作完成后，x 的值可能是（ ）。

A. 只能为 1  
B. 可能为 0、1 或 2  
C. 可能为 -1、0、1 或 2  
D. 原截图底部未拍到该项

**答案：B。**

**解析：** 两者都先读取 1 时，最后谁写入就可能得到 2 或 0；串行化执行时结果为 1。`-1` 不可能由这两次各执行一次的加一、减一操作产生。核心考点为“读-改-写”非原子操作的竞态条件。

## 二、编程题

### 编程题 1：统计能被 k 整除的十进制非空子序列

#### 题目

平台发放一个由 0～9 组成、长度为 n 的数字字符串 S。仅能按原顺序选出部分数字，构成**非空子序列**；被 k 整除的子序列计中奖。求有多少种按下标区分的非空子序列能被 k 整除，结果对 `1,000,000,007` 取模。

> 原截图强调“下标不同即视为不同种”；删除字符后保留原来顺序。不同下标得到同一数值也应分别计数。未见要求禁止前导零，故按照普通非空子序列计数。

#### 输入

第一行两个整数 n、k：`2≤n≤1000`、`1≤k≤1000`。第二行一个长度为 n、仅由字符 `0`～`9` 构成的字符串 S。

#### 输出

一个整数，表示满足条件的非空子序列数，对 `1000000007` 取模。

#### 样例

~~~text
输入：
4 3
1423

输出：
5
~~~

五种满足条件的子序列：`12、123、42、423、3`。

#### 正确思路与复杂度

维护 `dp[r]` 表示处理完当前前缀后，余数为 r 的非空子序列数量。遇到新数字 d，可选择不取（保留旧状态）、单独取（`d % k`）、或接到已存在子序列后（新余数 `(10r+d)%k`）。每轮使用新数组避免同一位数字重复使用。

- 时间复杂度：`O(nk)`。
- 空间复杂度：`O(k)`。
- 每一步严格取模，避免指数级计数溢出。

#### C++17（ACM 模式）

~~~cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    string s;
    cin >> n >> k >> s;

    constexpr int MOD = 1000000007;
    vector<int> dp(k, 0), ndp(k, 0);

    for (char c : s) {
        int d = c - '0';
        ndp = dp;                      // 不选择当前数字

        ndp[d % k] = (ndp[d % k] + 1) % MOD; // 单独成序列

        for (int r = 0; r < k; ++r) {
            int nr = (r * 10 + d) % k;
            ndp[nr] = (ndp[nr] + dp[r]) % MOD;
        }
        dp.swap(ndp);
    }

    cout << dp[0] << '\n';
    return 0;
}
~~~

### 编程题 2：笔记草稿箱配对（单点翻转 + 区间查询）

#### 题目

素材有两种：图文（0）与视频（1）。按顺序处理素材，草稿箱最多存一条素材，初始为空：

1. 草稿箱为空：放入当前素材；
2. 草稿箱非空且新素材类型**不同**：两条素材配对发布一条“图文 + 视频”组合内容，计数加一，清空草稿箱；
3. 草稿箱非空且类型**相同**：跳过当前素材，草稿箱不变。

有 n 条素材，编号 1～n，进行 q 次操作：

- `1 x`：翻转第 x 条素材的类型（0 ↔ 1），该操作影响后续查询；
- `2 l r`：假设草稿箱从空开始，仅处理闭区间 [l,r] 的素材，输出可发布的组合内容条数。

#### 输入

第一行 n、q：`1≤n,q≤10^5`。第二行 n 个 0/1 整数；后续 q 行分别为上述两种操作。

#### 输出

对每个 `2 l r` 查询输出一行答案。

#### 样例（本次对话截图）

~~~text
输入：
4 5
0 0 0 0
2 1 4
1 1
2 1 4
1 2
2 1 4

输出：
0
1
1
~~~

#### 调试复盘：原代码为什么 TLE、为什么计数有误

本次对话第一次尝试用线段树维护素材类型，再在每个查询里逐个位置调用线段树点查询、比较“相邻数字是否不同”。这存在**两个独立错误**：

- **时间复杂度不对：** 单个区间最坏 `O(n log n)`，q 次最坏 `O(qn log n)`。实际提交截图显示通过率 18%、约 4085 ms 并触发 TLE；另一张自测截图显示约 4078 ms、TLE。截图不能证明最终版本已在平台 AC。
- **业务逻辑不对：** 例如素材 `010`：相邻变化次数为 2，但依规则第一条 0 与 1 配对后清空，最后的 0 无法配对，正确答案为 1。不能仅计算区间相邻异或的和。

**最终采用“三状态区间函数”的线段树：** 把每段素材看成一个作用于“初始草稿箱状态”的函数。状态 0=空、1=图文、2=视频。每个节点分别记录初态为 0/1/2 时，该段产生的配对数量 `cnt[s]` 和处理后状态 `to[s]`。拼接左右段时用左段的结束状态作为右段初态，计数相加。由于区间函数合成具有结合律，适合线段树维护。下面采用**非递归线段树**，减少函数调用及区间遍历开销。

- 建树：`O(n)`。
- 单点翻转：`O(log n)`。
- 区间查询：`O(log n)`。
- 空间：`O(n)`。

#### C++17（ACM 模式：修正后的最终版本）

~~~cpp
#include <bits/stdc++.h>
using namespace std;

// 状态：0=草稿箱为空，1=图文，2=视频
struct Node {
    int cnt[3] = {};            // 三种初态对应的配对数量
    unsigned char to[3] = {};   // 三种初态对应的末态
};

inline Node identity() {
    Node t;
    for (int s = 0; s < 3; ++s) t.to[s] = s;
    return t;
}

inline Node leaf(int x) {
    Node t;
    int type = x + 1;           // 素材 0/1 映射到状态 1/2
    for (int s = 0; s < 3; ++s) {
        if (s == 0 || s == type) {
            t.to[s] = type;     // 空箱存入，或同类跳过
        } else {
            t.cnt[s] = 1;       // 异类成功配对
            t.to[s] = 0;        // 配对后清空草稿箱
        }
    }
    return t;
}

// 函数合成：先处理 L，再处理 R；合并顺序不能交换
inline Node mergeNode(const Node &L, const Node &R) {
    Node t;
    for (int s = 0; s < 3; ++s) {
        int mid = L.to[s];
        t.cnt[s] = L.cnt[s] + R.cnt[mid];
        t.to[s] = R.to[mid];
    }
    return t;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, q;
    cin >> n >> q;

    int base = 1;
    while (base < n) base <<= 1;

    vector<Node> tr(base * 2);
    Node id = identity();
    for (int i = base; i < base * 2; ++i) tr[i] = id;

    for (int i = 0; i < n; ++i) {
        int x;
        cin >> x;
        tr[base + i] = leaf(x);
    }
    for (int i = base - 1; i >= 1; --i) {
        tr[i] = mergeNode(tr[i << 1], tr[i << 1 | 1]);
    }

    while (q--) {
        int op;
        cin >> op;
        if (op == 1) {
            int x;
            cin >> x;
            int p = base + x - 1;
            int old = tr[p].to[0] - 1;
            tr[p] = leaf(old ^ 1);
            for (p >>= 1; p; p >>= 1) {
                tr[p] = mergeNode(tr[p << 1], tr[p << 1 | 1]);
            }
        } else {
            int l, r;
            cin >> l >> r;
            int L = base + l - 1, R = base + r - 1;

            int state = 0, ans = 0;
            Node right = id;
            while (L <= R) {
                if (L & 1) {
                    const Node &t = tr[L++];
                    ans += t.cnt[state];
                    state = t.to[state];
                }
                if (!(R & 1)) {
                    // 右半侧区间从右向左获取，需要前插
                    right = mergeNode(tr[R--], right);
                }
                L >>= 1;
                R >>= 1;
            }
            cout << ans + right.cnt[state] << '\n';
        }
    }
    return 0;
}
~~~

### 3.4 技术方案复盘与常见陷阱

- **一个明确基线 + 一个改进方案：** 对 28×28 灰度图可先使用归一化像素 + 欧氏距离，第二方案考虑 HOG/PCA + 余弦相似度；先以实际数据分析为准，不假定哪个必然更好。
- **分类标签用于评估相关性，不等于输入检索时能泄露查询标签。** 同一查询的候选索引、候选类别及真实查询类别要正确关联，尤其不能把“示例 JSON 里的数字”当作模型成绩。
- **公平比较：** 相同候选库、查询集和 K；分别报告两种方法的检索精度、mAP 和耗时，说明预处理/建索引是否计入耗时。
- **索引计算：** 对 10k 候选 × 1k 查询，避免百万次纯 Python 嵌套循环；可采用预计算特征、批量距离计算与 `argpartition` 后局部排序。若显存 / 内存受限，使用合理批大小。
- **指标口径：** 相似类别可作为“相关”的一种定义，但 Recall@K 的分母应是候选库中该查询的全部相关样本数量；mAP@K 的分母应按 README/选定约定明确定义。无关类别不能仅因像素相近就算“准确”。
- **最终产物：** 题目要求的是在可检查的工程约束下通过 AI 辅助完成项目；**本次对话只完成了提示词策略，未提供实际 CSV，也未运行这道工程项目或生成真实 result.json。**
